# Optional singing alignment backend research

**Research priority superseded:** see [native-first development audit](knowledge/DEVELOPMENT_AUDIT.md) and [community/evaluation research](knowledge/COMMUNITY_AND_EVALUATION.md). Native MMS/related HOT-Step timing and official evaluation are investigated before optional external alignment; no model approved for installation. Historical benchmark and reference tools remain research utilities.

Decision: investigate local mVocalToolkit + HubertFA first; no mandatory dependency, no automatic installation, no new inference yet.

Sources (reviewed 2026-11-25):
- https://github.com/qiuqiao/SOFA: singing-specific forced alignment, dictionary/G2P plus compatible checkpoint, TextGrid/HTK and confidence export. English checkpoint https://huggingface.co/Silasimo/SOFA-combined is CC BY-NC-SA 4.0; not a default for unrestricted use.
- https://github.com/wolfgitpr/HubertFA: singing-focused ONNX inference; language options include zh/ja/en/yue. CLI support does not establish availability or accuracy of a given checkpoint. Code Apache-2.0; model rights separately.
- https://github.com/Soul-AILab/SoulX-Singer/blob/main/preprocess/README.md: broader vocal, F0, lyric and note transcription; recommends reviewing generated metadata; more dependencies and scope than needed.
- https://github.com/Megageorgio/mVocalToolkit and https://github.com/Megageorgio/mVocalToolkit/blob/main/docs/API.md: local HTTP service, language catalog and modular alignment/segmentation engines, isolated environments, multiple output formats. MIT code, separate model/engine licenses. Its current documentation includes HubertFA model id hubertfa-zh-ja-en-v0.0.7. Young external project; not yet approved or tested. May auto-update on startup and automatically install missing engines/models on inference. Disable auto-update and review catalog/network behavior before use. Pin vetted versions and hashes before executing any third-party code/model. Do not expose service beyond loopback.

`alignment-preflight --language en --out NEW_REPORT.json --url http://127.0.0.1:8765` makes bounded read-only GET requests to /health and /languages?task=align. It reports only exact language entries and installed flags; it does not contact external model repositories, install, submit alignment, or send private audio or lyrics. Backend version/catalog contract is documented but not verified live. An unavailable or unknown catalog cannot authorize execution. No alignment job is submitted. Exact English/Chinese/Japanese candidate model ID is a research preference only, not an auto-selection policy. Indonesian and other languages require a verified model rather than silent cross-language fallback.

Next validation gates: audit pinned engine and model provenance/license; create isolated runtime, no auto-update; choose one short excerpt from existing vocal stem with a defensible source/time mapping; compare intended-text forced alignment to independently observed phonemes; validate confidence, omissions and timing using known boundaries. Do not treat forced alignment against expected lyrics as verification that the words were sung. Only after evidence of fit and a safe execution contract consider a full-song job. No repeat generation, stems or prior ASR. The director remains able to diagnose and select existing candidates without this optional backend.

## Offline benchmark

`alignment-benchmark --audio EXCERPT.wav --reference ANNOTATED.lab --candidate PREDICTED.lab --out NEW_REPORT.json`

Compares two saved HTK three-field phone interval files (integer 100 ns ticks, maximum 60 s timeline and 2000 intervals). Use an independently annotated reference and identical audio/phoneme inventory; do not use interpolated LRC or intended lyrics as a ground truth. Reports sequence edit distance; boundary errors in ms only when labels and order exactly match, with shared identical boundary pairs counted once. Reports signed/absolute mean, median, p95, maximum, 20/50 ms fractions and start/end means. Hashes the three inputs but does not decode audio or authenticate annotations. No correction threshold, no claim of verified pronunciation, no audio/ASR/model calls. Synthetic tests only; real benchmark awaits an authorized checkpoint and independently annotated sample. The benchmark cannot establish whether a forced label was actually sung.


## Independent reference data and bounded preparation (2026-11-25)

Do not ask the operator to repeatedly listen to their own song to calibrate alignment. Use a documented external singing corpus with independent reference labels, distinct from the model training set where possible:
- [NUS-48E mirror](https://huggingface.co/datasets/guey-khala-mari/NUS-48E): English, manually aligned phones in decimal seconds, research-only terms; not a commercial-use default. Check original corpus terms and annotation quality before use.
- [GTSinger](https://huggingface.co/datasets/GTSinger/GTSinger/blob/main/dataset_license.md): multi-language manual alignment, CC BY-NC-SA 4.0; restricted research use.
- [PJS](https://sites.google.com/site/shinnosuketakamichi/research-topics/pjs_corpus): Japanese singing, CC BY-SA 4.0; the author links a separate human relabeling project. Verify relabel license, recording correspondence and training-set independence before testing.
- [External benchmark](https://github.com/gillosae/phoneme-conditional-singing-analysis/blob/main/benchmark/README.md) reports significant variation in alignment accuracy across models and languages, and an offset annotation excluded from NUS-48E. Results are not our own benchmark or proof for YuE2 audio.

`alignment-reference --audio ANNOTATED.wav --annotation ORIGINAL.txt --unit seconds --first 1 --last 20 --out NEW_EXCERPT_DIR`

Use `--unit htk` for integer 100 ns labels. Explicit one-based inclusive interval range; selected labels must be contiguous, positive duration, nonoverlapping, and within actual PCM WAV frames. Up to 10 minutes input, 60 seconds excerpt. Copies exact PCM frames (nearest sample cuts), preserves channel/rate/bit depth, shifts boundaries into excerpt time, snaps outer endpoints to the cut, retains phone inventory, outputs excerpt.wav, reference.lab, phones.txt and a fingerprint report. No downloads, inference, resampling, or library changes. Reject unsupported/zero-length labels rather than silently normalize. No assertion that the chosen labels are ground truth, licensed, or independent from training data; caller must verify those properties. No corpus files are bundled. Tests use synthetic PCM fixtures. Checkpoint license/digest and runtime remain blocked; preparing reference evidence alone does not authorize a correction.

## Independent phoneme observation (2026-11-25)

The completed retained timing experiment provides display anchors, not observed phones. Do not repeat it. Native HOT-Step [model documentation](https://github.com/scragnog/HOT-Step-CPP/blob/master/docs/user/models.md) identifies MMS_FA as a forced aligner (upstream CC BY-NC 4.0), used for training and finished-render lyric display, with per-word spans. It is not an unconditioned recognizer. The public [Phonsa implementation](https://github.com/YatingMusic/Phonsa) offers unconditioned phoneme segmentation (MIT code) but its released model instructions primarily cover Chinese and Japanese; only Linux has been tested by its authors. Its English-through-pinyin mode does not establish English phone recognition accuracy. Do not install it for English/Indonesian by default. [SingAlign](https://huggingface.co/pymaster/SingAlign) releases singing checkpoints under CC BY-NC-SA 4.0; English rough-domain validation is limited. Alignment and independent recognition are distinct requirements.

A bounded research candidate is [Meta Wav2Vec2 LV60 phoneme recognition](https://huggingface.co/facebook/wav2vec2-lv-60-espeak-cv-ft) (Apache-2.0, multilingual Common Voice speech training) and its [community ONNX export](https://huggingface.co/onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX). The public [singing alignment benchmark](https://github.com/gillosae/phoneme-conditional-singing-analysis/blob/main/benchmark/README.md) used the unquantized speech-trained acoustic model with forced alignment; it does not validate our quantized unconditioned phone recognition. The quantized file is 317,712,852 bytes, SHA-256 3d1479b5c70836645a4310902479f7f7e8bbc8c16c58745d918804f4f6f9d120. Candidate snapshot c69750f5043e5e1f8a71ab95dd3b98338c280c92. Weights were not accessible from this environment (DNS failure). Vocab provenance/byte identity not verified; do not use an arbitrary same-size vocabulary.

`phoneme-observe --audio EXCERPT.wav --weights MODEL.onnx --vocab VOCAB.json --reference REFERENCE.lab --out NEW_REPORT.json --confirm-evaluation` is an optional offline research command. Uses only audio for the model input, 16 kHz mono normalization, ONNX CPU provider, CTC argmax collapse, bounded 1–30 s PCM input. Optional reference is compared afterward, must already match the exact token inventory and have independently documented annotation; no guessed phone mappings, pronunciation or silence normalization. The report records hashes and token disagreement, not verified PER, phone boundaries or a quality decision. Vocabulary hash records the supplied bytes, not authoritative identity. No Studio calls, download, training, new song or automatic correction. Regression tests exercise the decoder and mocked model-output contract; actual ONNX inference, dependencies, vocabulary identity and independent reference corpus still need validation. Do not ask the operator to install or test this research command before those inputs and the one-command logged benchmark launcher are ready.

Keep normal stock-model generation and finishing work independent of this optional research. Do not block an otherwise usable agent indefinitely on a universal phonetic evaluator; report uncertainty when language-specific evidence is unavailable.
