# Local owned locks and explicit recovery

Windows and Linux operation markers record an exclusive owner token, process birth identity, host and operation context. Inspect with `music.cmd --inspect-lock autonomous` (or `drafts`, `critic`, `creative`, `artwork`, `exports`, `feedback`, `finishing`). Inspection is read-only and makes no Studio/provider calls. It reports a bounded summary of relevant journal states, not their private contents.

Only a known local stale owner with inspectable context qualifies for recovery. After reviewing the journal states and exact marker SHA-256, the operator can use `music.cmd --recover-lock autonomous --expected-sha SHA --confirm-run` and type `RECOVER`. The original marker and recovery evidence are retained under `results/lock-recovery`. No journal is modified; no submitted, ambiguous or completed operation may be replayed because its process died. Recovery does not cancel Studio work or prove Studio is idle. Legacy empty markers, unknown owners, unsupported process identity, and uninspectable journals fail closed; do not delete them blindly. Never run another writer during recovery. A stale lock does not authorize another GPU/ASR/text call.

For a continuation that already has complete native and listening evidence but an unresolved Director attempt, `music.cmd --continue-plan JOB --retry-text director --confirm-run` authorizes exactly one additional Director text completion against the original frozen request and provider identity. Completed, missing, or exhausted attempts are rejected. Native and listening stages are not called. Do not use this command for a completed reference take.
