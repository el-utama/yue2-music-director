# Upstream and community prior art: reuse before development

Audit date: 2026-11-25. This is a research shortlist, not a claim that all public adapters or repositories have been exhaustively audited or approved. Repository names are not endorsements; similar "YuE2 Studio" projects are different applications. Read each actual model card, license, configuration and runtime source; pin revisions and checksums before any use. No weights, audio or external packages were installed for this audit.

## Official YuE2 agent and evaluation

The [M-A-P official repository](https://github.com/multimodal-art-projection/YuE) already provides an Apache-2.0 [yue2-music skill](https://github.com/multimodal-art-projection/YuE/blob/main/skills/yue2-music/SKILL.md) (reviewed blob 4764dd39d26f2b31514ee92eae2a2fcd61af8ccd) and [generation](https://github.com/multimodal-art-projection/YuE/blob/main/docs/generation.md), score editing and [listening/evaluation instructions](https://github.com/multimodal-art-projection/YuE/blob/main/skills/yue2-music/references/listening-and-evaluation.md) (blob e02c471676a829ee1aea816488810041cea8ad60). It supports generation, transcription/covers, symbolic edits, invariant checks and comparison workflows. Reuse the concepts and existing helpers where suitable; adapt I/O to native Studio MCP rather than installing a parallel full Python generator by default. Check actual helper dependencies, license notices, input contract and native artifact compatibility before importing code.

The official [benchmark scope](https://github.com/multimodal-art-projection/YuE/blob/main/docs/benchmarks.md) (blob 0a1a2612049576d5d256dac729376a2542d6f036) and [WildSongBench](https://huggingface.co/datasets/m-a-p/WildSongBench) provide a 192-prompt evaluation, separating musical quality, control and lyric metrics. Standard evaluation selects lower PER from two renders; best-of-8 ranks musicality, prompt control and PER; their selection uses four ASR passes per candidate for PER. This is not equivalent to one Studio ASR call, and the published comparisons have different compute budgets. The official benchmark decoder differs from the listening decoder. The editing evaluation contains 3,844 renders over 192 prompts and measures controlled score edits; it does not show exact waveform retention. Reuse protocols and prompts where terms permit; do not claim to reproduce the full benchmark on a single song.

Potential evaluator families: SongBench (melody, arrangement, musicality, vocal, instrumental, mixing, structure), SongEval, AudioBox PQ, MuLan, AllMusicCaps, Q3O and PER/CER. The complete evaluator kit is separate; the official skill explicitly warns not to fabricate a replacement if unavailable. Its saved-artifact verifier expects native SongResult metadata/arrays/tokens/latents/audio hashes; a Studio FLAC alone is not equivalent. Audit public availability, license, local resource cost, languages and adapters for Studio outputs before integrating. A minimal independently named text/technical check remains useful but must not be branded as official SongBench/PER. The previous Music Director WER/CER metrics are single native ASR text-disagreement screens, not the official PER protocol.

Official upstream documents state that YuE2 generation does not expose a dedicated phoneme override or generic local-inpainting argument. A designed syllable-to-note sidecar is not measured alignment. The planning/synthesis split, invariant checking, seed handling and separate evaluation already match our design goal; do not implement those from scratch without a documented gap.

HOT-Step documentation explicitly distinguishes training per-word spans from alignment of an existing render for display. This is a stronger reuse lead than writing a new native-MMS manifest generator. It does not imply that timoncool's current MCP exposes the endpoint; the pinned 339-tool source has no standalone MMS alignment tool. Audit the shipped music-train binary contract and exact backend revision first. No full training should be launched to obtain timing. Existing HubertFA/mVocalToolkit discovery, HTK benchmark and excerpt preparation remain optional research utilities, not prerequisites for the core agent.

No verified public universal pronunciation-fixing LoRA was established by this search. There is relevant prior art for natural timbre, articulation, instrument identity, rhythm conditioning and broader quality, but direct evidence for our songs, English/Indonesian pronunciation or the user's installed fine-tune remains absent. Do not download or train blindly. Search live lora_list and HF catalog first when local access exists; verify author, base, compatible slots, exact checkpoint, hash, trigger, source recordings, consent/license, recommended strengths and known failure modes. No private song data is sent to a model catalog. Model-license restrictions are a separate deployment gate from code licensing; obtain clarification before commercial use.

## Reuse plan

1. Use native writing guidance and score generation instead of rebuilding songwriting or score-planning controls. Keep our invariant checks as independent safeguards.
2. Use native library, replay, model selection, LoRA selection, stems, processing/export, training and checkpoint comparison under explicit job budget. Do not reimplement these mechanisms.
3. Investigate official evaluator availability and artifact requirements first. Use existing ASR disagreement evidence for low-cost screening; don't mistake it for quality or phonetic truth.
4. Prioritize read-only installed-model/adapter/capability discovery, then audit already-retained experiment evidence. Design future small controlled experiments only if needed, comparing no-adapter vs one compatible candidate with fixed base/decoder/companion/settings. No repeated existing generations for documentation. Training only if recurring cross-song issues remain after verified existing alternatives, with independent held-out data and explicit permission.
