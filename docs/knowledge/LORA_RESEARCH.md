# Public YuE2 adapters: research and selection policy

Reviewed 2026-11-25. Search targeted intelligibility, pronunciation, language, prosody, voice/instrument performance and production quality; inspected primary author cards and the [Awesome-YUE2](https://github.com/igrbible/Awesome-YUE2) discovery list, plus the native [39-entry catalog cross-reference](LORA_CATALOG_INDEX.md). Not exhaustive. No new weights downloaded, no model switch, render or training. The native local inventory succeeded in concise mode; keep individual local observations private.

## Critical base-model compatibility finding

The [RS fine-tune author card](https://huggingface.co/goldhub/YuE2-RS-Finetunes#adapters-on-these-weights) (section "Adapters on these weights") explicitly warns that stock YuE2-trained adapters can degrade voice/style on both RS-FW and RS-TW. Ruach Studio's own application recognizes mismatched bases and warns/mutes adapters when changing the backbone. RS-TW 2.0 is a merge built on RS-FW, not a stock checkpoint plus a single interchangeable style adapter. The author trains TW-specific adapters on TW 2.0 ×0.75. The card treats FW adapters as an imperfect match on TW, not proof of compatibility. Do not assume timoncool Studio implements the same compatibility checks. Merely loading without error, matching tensor shapes or being in native catalog is insufficient. Keep the current fine-tune unchanged; use stock YuE2-3B as a separate reference for stock-trained adapters if already installed and explicitly approved. Do not automatically install/switch. The active VAE, companion and checkpoint identity still need explicit verification. A TW-trained adapter is preferred for TW when provenance and actual compatible loader are verified; no verified public general-purpose TW pronunciation adapter was located.

## License and output rights

[Official model license](https://github.com/multimodal-art-projection/YuE/blob/main/MODEL_LICENSE) includes a 2026-09-16 additional permission for individual creators to generate and monetize outputs under responsible-use conditions. Weights remain CC BY-NC 4.0; this is not unrestricted commercial redistribution or company use of weights, nor rights in third-party inputs/outputs. The [HF weight license](https://huggingface.co/m-a-p/YuE2-3B/blob/main/LICENSE) and current upstream permission must be reviewed together. RS fine-tune card declares CC BY-NC-SA 4.0 and separate VAE-RS CC BY-NC 4.0. Do not assume official additional permission extends automatically to every derivative or third-party dataset/voice. Model cards for KTO, hum, RealAudio, sliders, and multiple styles declare noncommercial terms. Some other adapters have no explicit license; native catalog CC0 labels do not remove underlying base restrictions. Confirm exact terms, intended use, and rights/consent for each asset, particularly artist/voice adaptation. No blanket legal clearance.

## Agent decision requirements

1. Resolve goal (instrumental-only vs sung lyrics; specific timbre vs pronunciation vs timing vs production); select only interventions that address it. Prefer native score guidance and existing assets; no generic automatic adapter stacking.
2. Use live installed inventory to map actual IDs/slots and file provenance to public catalog. Noncatalog assets are unknown until local metadata/author source checked. Preserve exact base/decoder/companion/cache/runtime. Unknown base or unsupported stage/conditioning blocks automatic use; require explicit review. A native catalog default scale is a starting value for compatible use, not approval.
3. Verify file revision/hash, format, actual base, intended language/style, training/evaluation evidence, licenses and required companions. Keep locally; do not duplicate downloads. Separate technical load compatibility from musical outcome.
4. Before any approved test, preregister one variable, fixed comparable request, base, quantization, VAE/companion, score and seeds/settings. If trigger text must change, record the confounder and use appropriate matched controls; no claims of isolated effect when multiple factors change. Use retained source evidence where matched, not arbitrary old renders as controls. Define resource budget and acceptance metrics first. For instrumental work use unwanted-voice detection and score/style/quality checks; for sung work use lyric agreement, appropriate alignment/prosody, score adherence and acoustic/quality checks separately. Do not require routine user listening or substitute ASR for musical judgment.
5. Prefer verified installed candidates; download only if genuine unmet need and authorized. Native training is last resort for repeated cross-song gaps after existing alternatives, with licensed independent training/validation data and a compatible base. No generation, training or download in this research phase.

## Next steps

Complete offline use of existing experiment reports and check actual model/decoder/companion provenance locally. Investigate official evaluation compatibility and the native MMS/HOT-Step timing path; installed training pack readiness is not proof of exact alignment model or standalone CLI compatibility. Establish a base-aware adapter selection policy before any render. Revisit public catalog/model cards when needed for a concrete problem; prioritize evidence over adapter count. No implementation of a new model or trainer required.

Native Studio also has a score-strength error and `song_job_score_again` retry that creates another job with reduced composition scales. This is a mutating recovery operation, not a compatibility test. Do not invoke automatically or stack adapters at their independent defaults. Pinned `adapters.rs` identifies internally trained adapters as having used the frozen companion, reinforcing the need to record companion state; it does not establish arbitrary third-party base matching.
