# Development audit and revised roadmap

Date: 2026-11-25. Supersedes the sequencing in earlier alignment research documents; historical results remain intact. Primary references: [native capability knowledge](STUDIO_CAPABILITIES.md), [339-tool source index](MCP_TOOL_INDEX.md), [official/community prior art](COMMUNITY_AND_EVALUATION.md).

## Assessment of our earlier plan

We spent too many successive PRs building preparation wrappers and synthetic validation around an unvalidated external alignment backend. Native training's MMS stage, the official agent skill/evaluation protocol, native export, native score and generation controls, community fine-tunes/adapters and conversion were not comprehensively considered before designing that roadmap. This was a planning gap. Passing fixtures is evidence about software behavior, not product completeness or actual audio improvement. Do not continue stacking modules that do not remove the real blocker.

| Existing area | Overlap / genuine gap | Decision |
|---|---|---|
| MCP client and safe transactions | Studio already exposes typed operations, activity log and wait; agent still needs intent, budgets, provenance and safe recovery | Retain thin client and independent journal/ownership checks. Prefer native status/wait; no replacement service or UI. |
| ABC/phrase/MIDI humanization | Native planner, harmony, score editing, transformations and MIDI editor exist; official skill has invariant helpers | Retain validator and controlled diff; use native planning first. Custom pitch/velocity edits optional experiments only. Velocity MIDI output is not audio improvement. |
| Lyric screen / fidelity gate | Native ASR and syllable/section tools exist; independent assessment still useful | Retain current text-screen evidence, label limitations. Adopt official evaluator only after exact contract/license/resource audit. No compulsory repeated listening. |
| Audio finishing | Native effects, reference mastering, export ceiling and playback comparison exist | Native-first for deliverables. Keep independent FFmpeg QC and bounded preview gain continuation; custom stem-delta not default until demonstrated additional benefit. |
| Selector/director | Provisional choices, comparative evidence, safe stop are agent responsibilities | Keep, but currently fixture-tested combined decision. Its peak-first ASR ranking is engineering policy, not universal artistic ranking; ties/fallback may still need technical work. Do not call it full autonomous correction. |
| External aligner/preflight/reference/benchmark | Native MMS and adjacent HOT-Step tooling plus official evaluation exist; no calibrated phone evidence yet | Freeze feature expansion; optional utilities remain for validated research. Audit actual output and licensing first. Do not mistake forced alignment for observed phones. |
| Training | Studio has native datasets, preparation, LoRA/LoKr trainer, continuation, checkpoints, voice training | Do not build a trainer. Agent eventually manages approved training decisions and held-out evaluation. Existing public adapters/fine-tunes first. |
| Packaging, media, UI | Native export ZIP/DAW, library, player, covers and video already exist | Delegate to Studio; out of core scope until requested. |

## Revised product boundary

Music Director should be an **evidence-driven decision and orchestration layer on top of YuE2**, not a music generator, training framework, DAW or clone of its UI. It should understand goals, identify feasible native interventions, choose one with recorded rationale and resource limits, evaluate evidence with appropriate metrics, and stop or retain the best provisional result. A model cannot be declared universally better based on one song, ASR agreement, or an uncalibrated aesthetic metric. Separate score fidelity, language fidelity, artistic style/quality, acoustic technical readiness and model/rights compatibility.

## Gates in order (not an implementation backlog to execute blindly)

**Gate A — knowledge and installed capability inventory.** This source audit maps 339 static MCP names and major UI features; full live coverage is not established. Next collect one compact read-only capability snapshot on the actual local Studio: installed build and schema, active source/defaults, model/decoder/companion, GPU/runtime status, installed LoRA IDs/slots/triggers/base notes, recognizer/separator/training readiness. Only relevant reads; no private records uploaded, no downloads, no settings writes, no inference. Compare live to pinned source. Make a repeatable local entry point rather than many separate user commands; do not claim it exists until implemented and tested. If local access unavailable, record unknown, don't guess. Include installed model/adapter rights/provenance.

**Gate B — reuse actual retained evidence.** Run the existing combined director-diagnose against retained source/lyrics/ASR/custom/native reports once, with a fresh output. No audio generation, split, effect or ASR. Check that earlier selection code matches actual report schemas and baseline settings; do not force a winner from missing/invalid evidence. Current combined real-song validation remains outstanding.

**Gate C — official evaluation and community candidate fit.** Audit official agent skill/helper licenses and benchmark package availability, model resources and native artifact requirements. Adopt interoperable components or documented named lower-cost screens; do not create another evaluator pretending to be official. Resolve active base and adapter compatibility, including companion and VAE. Candidate selection from already-installed suitable adapters takes priority over downloads and training. Public models may be research/noncommercial restricted. Do not change the active model or generate now. Native export/read-only capabilities and existing native tools first.

**Gate D — targeted gap experiments.** Only after A-C, choose a concrete unmet need, e.g. recurrent English lyric errors, not generic "naturalize everything." For alignment audit exact Studio-pinned HOT-Step/MMS implementation and actual exported granularity/provenance; native or adjacent documented finished-song path may suffice for time cues. For actual phonetic diagnosis, distinguish observed/forced labels and use independent licensed annotations; verify training/test separation and runtime. If native output is only word timing, a true phone aligner remains a potential gap; external HubertFA/SOFA only if validated. For LoRA, compare one compatible adapter/strength against same base, lyrics, ABC, seeds, decoder/companion/settings; explicit compute limit, separate provenance, no old runs repeated merely for demonstration. For voice conversion use authorized reference only and verify whether desired change is timbre rather than pronunciation. Training is last resort for recurrent issues, not default after a failed single song. No automated overwrite/install/keep/delete.

**Gate E — unified execution.** Design a session-independent agent runner only after native inventory and real evidence compatibility. One operation budget, preflight, journal-before-submit, bounded wait, no blind retries, explicit authorization for generation/training/download/mutations, immutable inputs, evaluation and stop rules. Reuse upstream agent workflows rather than rebuilding inference. User should not routinely run many commands or perform listening tests. No claim of production readiness until independent real examples and recovery behavior are tested.

## Documentation governance

- English is the canonical language for all research, design, tests, knowledge and changelog; README also has an Indonesian overview/usage. Historical docs remain historical and link to current decisions.
- New feature proposal requires native capability search, community/official prior-art search, source links/revisions, overlap assessment, reason for any new code, actual acceptance criteria, and disclosure of unverified items. Update this knowledge base before implementation if capability changes. No implementation until a real gap is identified.
- Source inventory is not proof of installed availability. Record dates, revisions, evidence level (source, fixture, real local, third-party report), dependencies and license. Report failed/negative results. Do not publish private data, model weights, copyrighted source songs or credentials.
- Current blockers: no live connection to user's installed Studio from this environment; real combined selection untested; native standalone MMS output contract/rights not established; official complete evaluation package not yet located/validated; adapter compatibility and model rights not verified. Research audit reduces uncertainty but does not finish the product.

Gate A implementation: [local Studio profile](../LOCAL_STUDIO_CONFIGURATION.md) provides one read-only inventory command; actual runtime validation and mandatory pre-operation compatibility recheck remain outstanding. Original base model is optional as a reference baseline, not an installation prerequisite.

## Reference-model decision update

For the 8 GB CUDA tier, stock YuE2-3B Balanced Q6_K with stock VAE and no optional adapters is the initial reference, not a permanent production-model lock. Quality Q8_0 and community fine-tunes are optional comparison candidates. Native training requires at least 11 GB VRAM according to pinned upstream guide; do not prioritize training on this tier. See [configuration decision and intentional switch](../LOCAL_STUDIO_CONFIGURATION.md). Native capabilities first; adapters only for measured unmet requirements. No obligation to preserve or test all installed adapters. Do not delete assets or change model without authority.
