# Offline director diagnosis

`director-diagnose --source ORIGINAL.flac --lyrics LYRICS.txt --baseline-asr BASELINE.json --language en --custom CUSTOM_RUN_DIR --native NATIVE_RUN_DIR --out NEW_DIRECTOR_DIR`

At least one existing finishing experiment is required. Optional `--abc` must be the matching source score supplied by the operator. One invocation writes selection.json and report.json. The director checks source/reference/baseline fingerprints, reuses the finishing selector and reports lyric disagreement, English line-level minimum-edit localization and optional approximate score-rhythm cues. Headroom failures are marked for possible gain-only continuation; ASR regressions are rejected, invalid evidence requires verification. Existing eligible output is preserved provisionally, otherwise original is retained. No forced new candidate.

Execution budget is zero generation, native processing, ASR and score edits. The command cannot prove pronunciation or prosody from transcript edits, or infer causal timing from equal bar partitions. No verified phoneme alignment, no automatic lyric correction and no automatic library cleanup. Non-English global metrics follow multilingual_fidelity; English-only localization and word-density score analysis are not applied to other languages. This is a bounded diagnosis/planning component, not a complete execution loop. Native selection supports screened direct previews and headroom-continuation records. The report now ranks reuse of an existing provisional file first, inspection of existing native timing when lyric disagreements remain, and native export for a verified library source if a headroom delivery need remains. These are conditional recommendations, not submitted operations. No training or model switch is recommended based on these offline reports.

Do not repeat old experiments for this command. On 2026-11-25, real-song combined evidence review succeeded locally with exit code zero; a native candidate passed the technical gates while the custom candidate lacked headroom. No artistic winner or new inference. CI tests use synthetic local evidence. Reports must remain private; aggregate findings only belong in public research notes.

## Retained real-song review

After the successful local AudioBox run, Windows operators can use `review.cmd`. It recovers the matching completed finishing pair, resolves original audio through a read-only loopback library lookup, and finds the exact reference lyrics from the retained A/B manifest and baseline ASR JSON by digest. It joins the cached AudioBox report to screened files by digest, reports descriptive deltas, and preserves existing technical selection gates. No new inference, generation, processing, recognition, model download or settings changes. The launcher writes the private summary and errors to `results/review-output.txt` automatically; full local reports remain in a new director-review directory. Studio MCP must be running for source resolution. A missing or ambiguous retained record blocks rather than guesses. AudioBox scores cannot establish an artistic winner or calibrated improvement threshold. No default custom dynamics. Technical selection remains provisional. The integrated review has now passed on the operator's Windows PC. Synthetic writer-contract tests also exercise this path.

## Execute the retained timing recommendation

`timing.cmd` finds the already completed Director review, matches reference and candidate fingerprints and the saved evaluator evidence, uses the recorded source duration, and executes the existing read-only timing inspection. It never reruns the review, recognition, evaluator or generation. Studio MCP must be running. Output and exit code are saved automatically to `results/timing-output.txt`; detailed local timing evidence is stored beside the selected review. Display anchors, even with exactly matching written text, may be interpolated or stale and do not establish phonetic alignment. No lyrics, score, preview, or library mutation. If no usable karaoke exists, retain the provisional candidate and report that limitation. The new launcher requires real local validation; CI uses mocked Studio metadata.
