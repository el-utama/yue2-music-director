Date: 2026-11-26. Scope: music direction above YuE2, audio-aware evaluation, and practical production on the existing 8 GB CUDA system. This is a research decision record, not a new inference authorization or a claim of reproduced external results.

## What our matched test established

P4/P5 produced two liked or very similar takes of The Room We Left Behind from a fixed brief and reference configuration. The semantic score matched; the reviewed route did not edit it. The listener estimates approximately 95% similarity, not a measured similarity metric. There is no demonstrated artistic benefit from the extra planning step in this case. Direct native remains the default. The missing capability is an audio-informed creative decision, not another score parser or another identical render. Preserve the existing two takes and prior reference/listening evidence privately.

## Decision: close unchanged-score A/B; calibrate a critic before new generation

1. Reuse the private existing evidence: the preferred stock Twin Flames, the less-preferred Lampu di Jendela, and both liked/near-identical Room takes. Verify identity; do not commit or upload private audio/lyrics. The genres and other variables differ, so these are sanity checks, not causal controls or a test set sufficient for statistical claims.
2. Review already available CPU AudioBox evidence and current evaluator interface first; audit one candidate audio-aware verifier for license, runnable model/checkpoint, CPU/offload feasibility, memory and reproducibility. A separate local research-only environment is preferable. No installation/download or external audio service by default. If licensing or resource limits prohibit use, report unavailable and use existing permitted evidence and human listening.
3. Define a small per-song intent rubric from the actual brief: what should be heard, what evidence can test it, and what remains unknown. Separate musical intent, subjective listening, lyric delivery, technical quality, and provenance. Require each critique to name a specific observed issue, section or time window where supported, confidence/unknowns, preserved strengths, and a proposed action. No fabricated perception, universal pass score, or AI-detector objective.
4. Evaluate the existing recordings without generating new audio. A useful critic should distinguish genuine differences and uncertainties without forcing an artificial ranking of the two close takes. Check where it agrees/disagrees with listener observations, including genre confounding. Prioritize actionable evidence over numeric scoring.
5. Only after the critic is useful, authorize a fresh original song with direct-native baseline and, if warranted, one named revised prompt or selective musical control at unchanged settings. Freeze intended requirements and retain exact diff, seeds, costs and original. Compare against baseline with level-matched listening where practical. Do not replicate MIRA's nine-render budget. Additional inference, external services, finishing, training or publication require authorization.
6. Keep native finishing separate: an explicitly approved derived copy and audible improvement assessment, not destructive changes to source or proof that clipping caused the drum artifact.

Success criterion: a new director decision must be both musically meaningful and supported by an observation, not merely another generation or a higher opaque score. Existing runner, parser, stable-idle barriers and journals remain the execution foundation. No new phase is claimed implemented by this document.

## Source implementation located — 2026-11-26

The operator supplied the correct nested directory: https://github.com/mirareview/MIRA/tree/main/MIRA. The prior missing root README is superseded by the successful read of MIRA/README.md. Inspected source pinned at commit [29bb5be6320ea2e96b6490ef0793d4d2e8173485](https://github.com/mirareview/MIRA/tree/29bb5be6320ea2e96b6490ef0793d4d2e8173485/MIRA). The full tree contains executable Python source, dependencies and tests. No upstream installation, test execution or model inference performed. Repository metadata reports no license and the complete tree contains no LICENSE file; no permission to redistribute/adapt source established. Study architectural ideas; do not vendor code without permission.

- `intent/requirements.py`: text LLM extracts up to 24 concise audio-checkable requirements; exact structured controls, reference-name checks and negative/reference-safety items are filtered. Our must constraints need separate enforcement, not just rubric averaging.
- `optimizer/musicflamingo_scorer.py`: individual full-audio forward passes compute normalized yes/no token mass; additional targeted textual QA on weakest items. This is a model judgment, not calibrated confidence or listening proof.
- `optimizer/repair.py`: generates a complete alternate style prompt rather than accumulating repair notes; guard rejects certain new numeric specifications, clips to 110 words, and preserves passed requirements in instructions. `optimizer/runner.py` can freeze supplied lyrics. Preserve user lyrics unconditionally unless expressly authorized.
- `optimizer/tree_memory.py`: parent/child deltas, sibling contrast at same depth, deadband, preserve/repair cues; item-scoped, not cross-song learning. `optimizer/selector.py`: final selection prioritizes mean rubric score, then pass rate, low tail and minimum; our listener and non-negotiable gates remain distinct. Do not inherit universal 0.60 threshold.
- `providers/yue2.py`, `scripts/yue2_server.py`: isolated local HTTP worker using Python yue2-infer==0.1.5, resident YuE2Pipeline, fixed seed, durable task identity, WAV and checksums; not Studio MCP or yue2.cpp. Worker passes style, lyrics, cot and seed; no explicit duration cap in the worker call. Instrumental mode experimental. Keep our validated stock Studio gateway, resource limits, idle checks and journals.
- `config.py`, `providers/caption.py`, `requirements/evaluation.txt`: configurable OpenAI-compatible text endpoint defaults to Kimi 2.6/Moonshot; local MusicFlamingo using Transformers and device_map=auto. No verified 8 GB resource budget, quantization or explicit unload between resident generator and verifier in inspected code. Default external text calls and reference tools require privacy/permission review. Do not reuse an unrelated API key against the default Moonshot endpoint.
- `optimizer/runner.py` requires 3 or 9 candidates in MIRA mode; each round generates audio and scores requirements. Our bounded one-baseline/one-justified-revision approach is deliberately not a reproduction of their full search.

Engineering decision: retain existing execution layer; independently implement a small evidence/rubric and critic-provider boundary, first score existing retained recordings without synthesis, then test a single meaningful style revision only if useful and authorized. Verify evaluator model license and actual CPU/offload feasibility before installation; no external audio transfer or new GPU job authorized. Public source availability does not resolve checkpoint licensing or demonstrate natural singing on our hardware.
