# Repository agent instructions

**Mandatory project memory:** first read [PROJECT_MEMORY.md](PROJECT_MEMORY.md), the live requirements and evidence register. Compare the current request against all relevant requirement IDs, actual code, data inventory and CI. Update the register in the same change when evidence, requirements or blockers change. Do not equate a completed PR, passing CI or P0 alpha with the complete product. No requirement may disappear because it was postponed. Before reporting readiness, review end-user workflows and realistic inputs, not just function tests. Record omissions and unresolved issues explicitly; do not make the operator rediscover them.

Read [the active autonomous product roadmap](docs/AUTONOMOUS_MUSIC_DIRECTOR_ROADMAP.md) first. The [generation-first architecture](docs/MUSIC_DIRECTOR_ARCHITECTURE.md) defines native execution, evidence and recovery rules. Existing historical experiment gates remain in force. Read [the current native audit checkpoint](docs/NATIVE_AUDIT_CHECKPOINT.md) and [local release checkpoint](docs/LOCAL_RELEASE_CHECKPOINT.md) before resuming work; do not repeat completed tests. Remote audit access is restricted to the [documented bridge scope](docs/RESTRICTED_AUDIT_BRIDGE.md).

- Prioritize the P0 natural-language-to-song autonomous CLI on the Windows Studio host; Composer, Lyricist and configurable Nemotron provider are critical path. P0 is a bounded local alpha, not full product acceptance. Corpus, artistic knowledge, Artist Memory and multi-device operation remain tracked requirements even when not on the P0 critical path.
- Inspect actual source and native capabilities before implementing. Follow [the native control contract audit](docs/knowledge/NATIVE_CONTROL_CONTRACT.md): trace UI → schema → handler → conversion → engine input; distinguish native MIDI playback, score conditioning, and acoustic generation. Do not infer model control from UI or schema alone. Complete the relevant audit before adding performance or humanization specialists. Preserve prior evidence and local journals; never retry ambiguous external mutations or repeat completed inference. Keep Studio loopback and GPU jobs sequential. No model download, training, settings changes, new generation outside explicit budget, or publication without authorization.
- All private audio, unpublished lyrics, personal artist profiles, credentials, and local logs stay local and Git-ignored. Only use rights-compatible reference data; no detector evasion.
- Test offline with mock providers and failure injection; executable changes require green Windows/Linux CI before merge. Distinguish CI success from live execution and artistic quality. Use one short Windows launcher and a concise TXT report; operator is on another device.
- Keep technical documentation in English, current roadmap and evidence status accurate. Do not claim a role/service or dataset is built when it is only designed. Before reporting completion, audit README entry points, command flags, actual manifests, CI evidence, privacy/rights boundaries, recovery steps and live acceptance gaps; update the relevant guide, CHANGELOG.md and PROJECT_MEMORY.md in the same PR. Use [offline knowledge workflow](docs/OFFLINE_KNOWLEDGE_WORKFLOW.md) as the consolidated user guide for the three indexes.

## Operator and developer entry points

Use [Operator guide](docs/OPERATOR_GUIDE.md) for the actual supported workflow and recovery, [Development](DEVELOPMENT.md) for the current engineering entry points, and PROJECT_MEMORY.md for open requirements. Historical checkpoints are evidence, not the current main or a request to rerun old tests. Run the offline documentation regression tests with the normal suite; they check tracked inline relative links, heading fragments and primary launcher route coverage, not external link availability or live behavior. Before giving a command, check the current module and confirmation scope. Do not request a new checkout, configuration or inference on an already working host merely for verification.

## Modular failure isolation

Separate provider, Composer, Lyricist, editorial review, native adapter, audio critic, persistence and interfaces. Keep role contracts independently testable. Save immutable per-stage inputs and receipts; failure must not replay completed upstream stages or trigger downstream work. Resume only validated matching identities; ambiguous mutations require explicit recovery. Test stage failures, cache integrity and non-duplication. Modular code in one process is not process-level fault isolation; persistent worker supervision is a later requirement.
