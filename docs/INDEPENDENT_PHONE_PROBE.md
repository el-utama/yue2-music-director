# Independent acoustic phoneme probe (research only)

The retained real-song workflow has passed technical selection and partial native karaoke inspection. Do not repeat those tests. The missing capability is independent acoustic phoneme evidence, not another forced alignment against intended text.

## Candidate selection, 2026-11-25

- [HOT-Step-CPP model documentation](https://github.com/scragnog/HOT-Step-CPP/blob/master/docs/user/models.md) describes the MMS_FA GGUF (1.3 GB, CC BY-NC 4.0 upstream) for per-word cursor spans and finished-render lyric timestamps. This is forced word timing, not independently decoded phonemes. Do not install a training pack or train a LoRA for this purpose. Do not assume the newer HOT-Step endpoint is present in the operator's Studio.
- [Meta Wav2Vec2 LV60 eSpeak Common Voice](https://huggingface.co/facebook/wav2vec2-lv-60-espeak-cv-ft) (Apache-2.0 per card) recognizes phonetic labels from 16 kHz speech. It accepts audio without supplied reference text. This is the desired independent hypothesis mechanism, but speech-to-singing and English/Indonesian performance remain unvalidated.
- [Published singing alignment benchmark](https://github.com/gillosae/phoneme-conditional-singing-analysis/blob/main/benchmark/README.md) reports a 22.1 ms median boundary deviation on NUS-48E for a speech-trained IPA model with their specific forced-alignment pipeline; 72.3% within 50 ms. These are authors' boundary results, not independent phoneme recognition error rates and not our benchmark. Their fine-tuning brought modest gains. Never transfer those numbers to our greedy decoder.
- [SingAlign](https://huggingface.co/pymaster/SingAlign) offers English and Mandarin singing-specific forced-alignment heads, with published held-out boundary evaluation. Model rights, exact inventory mapping, dependencies and independent decoding capabilities require further audit. This is a different task, not a substitute for recognition. Qwen3-ForcedAligner also provides word/character timestamps rather than independent phone sequences.

## Narrow implementation

The optional [ONNX Community conversion](https://huggingface.co/onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX) lists Apache-2.0 and derives from the Meta checkpoint. Pin revision c69750f5043e5e1f8a71ab95dd3b98338c280c92; full precision onnx/model.onnx (1.26 GB), published SHA-256 93265694093f5f91497181ed9d7791f43bc818d2e23c46caf988fd9b8b1a1fba. The 318 MB INT8 variant is not equivalent by assumption, so do not use it for the first full-precision reference. Vocab has 392 IDs, blank 0, special IDs 1–3. The exact vocabulary digest is not yet independently verified: use only vocab.json from the pinned revision and record the actual hash; do not trust an arbitrary reordered inventory. The probe explicitly marks vocabulary provenance unverified. Configuration uses mean/variance normalized 16 kHz audio, attention mask if the ONNX graph requires one, logits argmax with CTC repeat collapse before blank removal. No pickle or dynamic model code, no network, no automatic installation.

`python -m yue2_music_director.phone_probe --audio EXCERPT.wav --weights model.onnx --vocab vocab.json --reference PHONES.txt --out NEW_REPORT.json --confirm-probe`

Requires a separately installed CPU ONNX Runtime and NumPy, 1–30 s mono PCM16 WAV at 16 kHz, and a fresh report. Reference optional, whitespace-separated independently annotated phones in the exact model inventory. No G2P conversion or silently discarding unsupported symbols. A missing hypothesis counts as deletions. Reports descriptive token disagreement, not a validated pronunciation score; unknown predicted symbols remain in the hypothesis. No timestamps, automatic acceptance, correction, regeneration or library changes. Model and input bytes checked before and after use. Synthetic tests check decoding and contract, not actual ONNX execution. No local model download or run has been authorized or completed.

## Actual acceptance gate

Before asking the operator for another Windows test, establish rights and inventory mapping for a public independently annotated singing reference, verify the vocabulary bytes and runtime compatibility, and prepare a single repo launcher with automatic TXT output. Use a small held-out reference set; do not use the operator's private lyrics, interpolated LRC or text-to-phone output as acoustic ground truth. Measure independent token disagreement separately from forced-alignment boundary error. Compare native word timing only if it adds diagnostic value. No fixed acceptance threshold until calibrated. Preserve current native candidate. Do not force an external backend as a requirement for all songs; language-specific applicability must be demonstrated. No automatic downloads or repeated old inference.
