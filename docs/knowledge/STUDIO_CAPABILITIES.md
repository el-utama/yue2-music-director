## Architecture and ownership

Studio is a native application with a Rust service, a Tauri UI and multiple local engines. It exposes its own MCP server, writing skill, guides, UI operations and Activity journal. YuE2's AR side generates the score and semantic music tokens, its NAR side synthesizes acoustic latents, and the VAE decodes audio. Changing a score is not a local patch to rendered waveform. Other supported music engines have different controls; never send YuE2-only parameters to another model by analogy.

## 1. Capability discovery, settings, environment and agent workflow

Start with studio_status, studio_capabilities, models_status, song_defaults, system_gpus and only relevant runtime/status tools. Identify active engine/model, installed providers and resource contention, not just advertised catalogs. Inspect exact schemas with tools/list. settings_get and engine_options_get are inspection; their setters, model select/download/remove/adopt/preset, runtime installation, network settings, storage relocation and package update/rollback are explicit state changes. Do not download, activate, remove or change settings just to perform an audit. Native/third-party engines and CUDA/Vulkan/HIP/CPU paths have different availability; training GPU requirements are separate from inference. Platform support is version-specific. OpenRouter may transmit data and incur charges; no implicit fallback. Community fine-tunes and VAE models can replace parts of the active model. Pin model identity, quantization, decoder, companion, engine revision and relevant settings before comparison.

Use native writing_guide and writing_examples; upstream provides song/style/lyrics/score/transcript/sections topics and representative official examples. Local assistant, remote assistant, connected MCP agent, and agent CLI are provider choices, not equivalent results. When user chooses Agent (MCP), assistant_requests_wait and assistant_request_answer support the Studio's writing workflow; do not build another writing UI merely to reproduce it. Headless mode, UI navigation/controls/screenshots and create_form_get/set/submit exist; UI actions can still mutate state. Prefer native direct typed tool calls, check actual UI for UI-only functionality. Do not rely on the Activity journal as sole completion proof: it records starts, not necessarily completed results. studio_wait is bounded (up to 55 seconds per call in this revision); retain job IDs and poll read-only, never resubmit on uncertainty. Avoid overlapping heavyweight GPU jobs. Agent should expose an authorization boundary and persistent operation budget, not duplicate Studio's queue.

## 2. Writing, score planning and generation

Style: use the native prescribed English style syntax (language, genre, vocals, instruments, mood, production, BPM); keep actual lyrics in requested language, tagged by section. Use native exact tokenizer song_tokenize where supported rather than guessed token counts. The writing guide permits stress hints in particular lyrics (e.g. combining acute); these are text hints, not a phoneme-control API. lyrics_syllables estimates the layout used by the score; not measured pronunciation.

Native score_compose can produce multiple ABC plans without rendering audio. score_job_get returns plans and seeds; choose a plan before costly synthesis. score_mark, score_vocal_octave, score_instrumental, score_from_midi and score_to_midi handle specific score transformations and interoperability. score_chord_bed generates chord-only structures with rests under explicit key, tempo, meter and section constraints. score_backing_tempo and score_backing_harmony analyze a saved recording; harmony suggestions can omit uncertain intervals. score_transcribe uses SheetSage2 for melody/chords from audio; score_match_sections proposes lyric-section tags based on recognised source audio and flags uncertain blocks. Not exact acoustic phoneme alignment. The score editor and MIDI grid expose native editing and import. Keep/Words modes, chord mirroring, transpose and sections are UI/native controls; discover exact installed schema before use.

song_create: explicit music_source.kind local for YuE2, style, lyrics, optional ABC, cot full/melody/off, seed and lm_seed, independent ABC/semantic sampling, guidance/steps, output, duration cap, batch sizes, solver midpoint/ab2. Score prefix continuation (abc_continue) can turn a hum/transcribed opening into a full arrangement. harmony settings control chord repetition/variety, outside-key suggestions and section adherence during planning; ignored with full supplied ABC. lyric_timing is section synchronization, not word/phone control. Do not assume that score preservation guarantees exact acoustic performance. Retain request, score, output lineage and actual model details; save each take separately.

Native covers use score transcription and section matching; audio-reference routes such as MuLaCover have different model requirements. Re-render/replay can resynthesize saved semantic codes (engine dependent); the UI also exposes extend/continuation and parameters reuse. Inspect actual saved replay request/audio codes through detailed library_song_get. Same seed does not prove deterministic waveforms; keep planner seed, synthesis seed and all settings fixed and use replicated comparisons if investigating effects. For decoder-only comparisons use exact same latent artifact where supported, not new score/generation.

Native backing_song_id: requires local YuE2, instrumental library song, matching chord bed, lyrics and ready separator. Can retain backing while generating/mixing vocals; it is not verified note-for-note reproduction of an arbitrary full existing ABC vocal score. vocals_only invokes separation after synthesis and requires the specified compatible output formats. rvc_after can generate a separate converted take; additional work and mutation, not free. Do not enable automatically. Native score controls are primary; custom pitch proposals only when the requested change is not covered by native operations, and verify invariants before any render.

## 3. Existing audio, vocals and music analysis

library_song_files identifies actual files; detailed metadata includes provenance where provided. lyrics_recognise uses configured karaoke ASR; actual earlier calls returned text/provider, not confidence or timing. karaoke_make generates word-highlight LRC in library; may overwrite existing data. karaoke_set accepts supplied subtitles/edited text. The upstream karaoke path fits expected lyrics to recognised word starts and interpolates unmatched words; a readable LRC is not proof of pronunciation. See [temporal evidence](../TEMPORAL_EVIDENCE.md). For native training MMS alignment see [LoRA audit](../NATIVE_LORA_TRAINING.md); it is forced timing, not independent phone recognition.

stems_split uses HT-Demucs (six sources) or Mel-Band RoFormer (vocal/instrumental); existing split can be replaced, do not repeat if already adequate. stems_get gives status and derived tracks. The native mixer plays synchronized stems with per-track controls. Audio-to-MIDI tools transcribe polyphonic/instrument content using the installed runtime; midi_get and library MIDI file tools expose results. MIDI editor/piano roll provides editing, instrument/drum tracks, import and export; a GM/SoundFont render is not native YuE2 audio. Score-export MIDI velocity defaults are not a direct conditioning channel of generated audio. restore_start (Apollo) addresses codec artifacts, not general lyric or performance defects.

recording_describe_style and library_song_describe_style use MOSS-Music plus tempo measurements and optionally a writing provider. Read-only from an analysis intent perspective is not zero GPU use; inspect mutation behavior before invoking. Useful for descriptive QA and reference style, not a calibrated perceptual score. SheetSage2/MERT2, Beat This!, ASR and MIDI transcribers offer complementary evidence, but not universal validated quality judges.

RVC voice conversion: rvc_backend_status / rvc_native_runtime_status / rvc_voices_list for readiness; curated voices/import and training require permission and provenance. rvc_preview produces a time-aligned fragment pair without library mutation (still inference); rvc_apply converts separated vocals, mixes with existing backing and saves a new song. Quick jobs can reuse prior outputs. seed_vc_apply uses a short reference sample (1–25 s), uploaded through processing_set_reference, and saves a new take. These can address timbre/identity, not guaranteed pronunciation repair. RVC Burn training is distinct from YuE2 composition/sound LoRA. Use only authorized recordings/voices and check compatibility and rights. Never train or convert by default.

## 4. Audio finishing and delivery

processing_start runs supported native stages: denoise, lifter, naturalize, VST chain, reference master and normalize, in stage order. An optional region is supported; a region preview is different from full-mix output. processing_get inspects pending run; processing_keep creates a derived library song; processing_discard destroys pending preview. These are writes, require ownership and explicit authority. [Detailed processing contract](../NATIVE_PROCESS_AUDIO.md). Naturalize is band processing with modulation/smoothing, not note/phone correction; lifter shapes spectrum/transients, not MIDI note velocities. Native peak normalization is not a true-peak ceiling. VST availability, parameter schemas and licenses depend on installation. Reuse built-in effects before custom DSP; custom stem-delta remains experimental and is not a verified superiority claim.

**Important missed feature:** song_export can output new WAV/FLAC/MP3 with explicit sample rate, depth/bitrate and optional loudness target and true-peak ceiling; it uses one gain, not a limiter, reports before/after values and when the ceiling prevents reaching target, and leaves the library song untouched. song_export_get and song_export_cancel manage the export job. Prefer native export for library deliverables rather than a new general-purpose mastering/export implementation. Existing FFmpeg acoustic checks remain independent QA; gain continuation of an uncommitted preview is a narrower case where song_export may not apply. Validate exact local behavior rather than auto-keeping previews solely to export them. Native song_export_live bundles a DAW project, song, available stems/MIDI; song_export_zip preserves existing original assets and metadata. Use these rather than constructing duplicate package tools.

## 5. LoRA and training

lora_list shows installed adapter IDs, slots, triggers, defaults and catalog; lora_search_hf/lora_hf_files locate community files; install/import/update/delete mutate. Import folder and safetensors formats are native. Native generation accepts adapter IDs and per-slot scales. The actual slot keys and strength defaults must be discovered, never hardcoded from another UI. Composition (AR) and sound (NAR) roles differ. A sound adapter does not guarantee a specific phoneme, and AR adapter may disturb a supplied score. In engine/source code the real-audio companion is recognized specially to avoid double merge. Some community models already merge adapters; companion Auto behavior depends on base/adapter. Freeze explicit companion scale for controlled trials. [Adapter implementation](https://github.com/timoncool/YuE2-Studio/blob/ca37d2d3ea96f3c7073167de0e5e1eb3b4ec2f25/crates/music-server/src/adapters.rs).

Native dataset/trainer handles import from folder/library, labels/styles, readiness, MOSS/tempo/ASR preparation and optional agent-written metadata, checkpoints, continuation and installation. No need for custom trainer. dataset_prepare may access lyric services, run separator/ASR and write metadata; can start training, so never treat as preflight. training_status detailed gives readiness, recipe defaults/fields, hardware, datasets, loss/KL/checkpoints. Use native checkpoint comparison only under a render budget; it creates a base and one sample per saved step and reuses saved takes. Recipe presets differ: base-matched disables lyric timing; tuned optionally invokes native MMS alignment. See [training audit](../NATIVE_LORA_TRAINING.md). RVC/HeartMuLa/Stable Audio training tools are separate engine-specific features, not YuE2 LoRA interchange. [Community knowledge](COMMUNITY_AND_EVALUATION.md) lists reusable prior work and licensing caveats. Do not start a training run solely because a single song had ASR errors.

## 6. Library, playback, visuals and adjacent native engines

Native library handles imported tracks, versions/derived stems, likes, album ordering, metadata/tags, notes, playlists and preferred take selection, trash/restore and deletion. Files panel exposes audio/score/MIDI/lyrics/covers/video. Use library IDs from the actual tools. Never overwrite, delete or empty trash by default; provenance and retained takes support comparison. Preferred take selection is a write, not automatic final acceptance. Playback includes player queue, equalizer presets, stereo/mono/balance, waveform, visualizer, Winamp skin mode, two-deck DJ and take comparison; playback EQ is not an audio edit. Some are UI-only or need window visibility. Native cover tools draw/import/select backgrounds/patterns, with provider setup; image generation may use cloud. Video editor supports text/karaoke/visualizers/backgrounds, aspect ratios, export and preview; it may need visible window and additional GPU work. These are out of the current music director's core scope; do not recreate them. Sound effects, ControlFoley and additional music/voice families (native ACE-Step/MiniMax, audio.cpp YuE2/HeartMuLa/Stable Audio, MiniMax-H3, MuLaCover, SoulX-Singer, Vevo2, and other catalog engines) have separate contracts, model assets, licenses and output modes. The exact supported set is discovered from capabilities/catalogs, not assumed from names. Keep external generation/provider changes opt-in; no engine substitution in a controlled YuE2 experiment.

## 7. What is known live vs source only

One earlier local song experiment verified score_to_midi, local generation, Whisper ASR, RoFormer separation, native Naturalize preview retrieval and headroom continuation with pending-run ASR. The custom offline stem-delta path ran on one song. The rest of this inventory is primarily source/documentation evidence. We have not accessed the user's current Studio window, verified current installed catalog, executed voice conversion, export, training, other effects, official evaluator or native MMS alignment. No new inference or installation was performed in this audit. Source coverage is broad across all static tool groups and primary guides; not a line-by-line verification of all engine implementations, UI-only features, releases, providers or every individual tool. The next action is discovery of actual installed capabilities, not implementing missing-by-assumption features.

## Maintenance rule

Before a new feature PR: state the intended problem, search this knowledge base and exact upstream source, check runtime capabilities, review official/community implementations and licenses, explain why native or reusable functionality is insufficient, and record an acceptance test. Refresh the MCP index from a new pinned source when upgrading; note changed/removed tool schemas and UI-only features. Do not copy old claims forward without status review. Keep all private song, dataset, recording, path, ID, manifest and checkpoint information local.
