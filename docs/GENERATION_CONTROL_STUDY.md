# Generation Control Study

First-generation musical naturalness is the product objective. The failed localized lyric-repair series is closed; it is not a prerequisite for generation. The current native draft sends song_create immediately, so its first score cannot be screened before full synthesis. Start with a measured native planning control, not another audio repair or arbitrary score randomizer.

## Study 1 — section-aware planning

Use the existing private brief, same stock Balanced CUDA/Q8 reference, fixed planner seed, full mode, one plan per arm. A is default native score_compose; B differs only by harmony.follow_lyrics=true. Studio maps lyric labels to engine harmony.follow, which steers section tokens and ending logits; it is not a proof of a complete or sung section. The native engine path uses a one-second budget and one solver step internally to return the score, so this is two lightweight GPU planning jobs, not zero GPU work. No full-length song generation, new model, ASR, download, repair or training. Native Studio may internally retry invalid plans; budget counts submitted jobs, not engine-internal attempts.

Source: [Studio MCP](https://github.com/timoncool/YuE2-Studio/blob/192363f16feae73a70c9ef5de79ca3d435c9b84d/crates/music-server/src/mcp.rs#L1892), [compose request and result](https://github.com/timoncool/YuE2-Studio/blob/192363f16feae73a70c9ef5de79ca3d435c9b84d/crates/music-server/src/lib.rs#L13328), [harmony mapping](https://github.com/timoncool/YuE2-Studio/blob/192363f16feae73a70c9ef5de79ca3d435c9b84d/crates/music-server/src/harmony.rs), [engine steering](https://github.com/timoncool/yue2.cpp/blob/892b9b0311512a1c45e42d6403881d17a991b87c/src/harmony.h).

Run from repo on Windows: `generation-control.cmd` is no-op plan, `generation-control.cmd --confirm-plans` authorizes the two sequential planning jobs. Existing journal resumes a known job; ambiguous receipt blocks. Saves both raw scores, receipts, structural report, local TXT log. The strict existing ABC subset can reject legitimate unsupported scores, including minor keys; mark these unassessable, not engine failures. Compare explicit tagged section order and note-bearing vocal occurrences, note counts, equal voice layout and score duration versus brief cap. Extra unrequested all-rest vocal sections are allowed. These are conservative first-pass structural gates, not judgments of lyric delivery, exact breath timing or musicality. Do not modify original audio or automatically choose/render a score.

## Subsequent decision

After live evidence, compare plans and retain any eligible plan; if both pass, no proven benefit from follow_lyrics on this brief. If both fail, diagnose the planner rather than immediately synthesize. If one passes and one fails, investigate generalization before making the control default. No universal conclusion from one seed/brief. A subsequent separately authorized generation-first test on a new song can compare default synthesis versus a pre-reviewed score, with fixed model, style, lyrics and seeds; record full-song generation time, number of takes and first-pass acceptance, technical and lyric non-regression, and matched blinded musical-naturalness listening where practical. Neither detection score nor a successful CI job establishes humanization. Later compare melody/full/off and compatible AR/NAR adapters independently only when a concrete unmet goal remains.

The study is not the final agent. Once pre-synthesis controls are empirically useful, integrate them into the existing one-brief workflow instead of adding permanent research wrappers. Do not use fixed detector-score targets or spend more resources on the failed outro.
